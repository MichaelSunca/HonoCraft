# HonoCraft

面向开发者与小型团队的单租户 SaaS / 企业后台脚手架，提供认证、用户管理、角色权限、安全审计和基础运维能力的设计与实现基础。

每个部署实例服务一个企业或业务系统，支持多个用户与角色。项目不包含多租户隔离、在线订阅或支付功能。

## 当前状态

项目处于 P0 开发阶段，尚未形成可运行的完整后台。

- **系统设置**：已提供品牌与安全策略分组读取、整组版本更新及中英文管理页面；安全策略仅真正超级管理员可保存，要求近期验证、原因与输入确认。支持角色搜索、冲突比较、响应不明时同键重试，缩短会话期限会同步收紧已签发会话。
- **日志查询 API**：已提供管理审计、安全事件和邮件任务的只读列表/详情，按各自权限查询、筛选和分页。审计保存脱敏操作者名称快照；查询再次限制历史 JSON 与自由文本，不返回匿名目标摘要、完整收件人、凭证、载荷、租约或供应商原文。
- **日志页面**：已接入审计、安全事件和邮件任务页面，支持 URL 筛选/分页、详情抽屉、显式刷新、中英文及只读权限导航；用户详情可按目标跳转审计。邮件详情区分已受理与已送达，并提供原业务流程入口。
- **媒体 API**：已提供本人头像、品牌 Logo/Favicon 上传与删除；受限工作线程校验像素、去元数据并重编码，按当前引用和资料可见范围读取，生成 32/64 像素 Favicon。版本或审计失败保留原图片，同键重放返回最小摘要。
- **图片页面与回收**：个人资料页支持头像上传/移除，设置页支持 Logo/Favicon，登录页和工作台同步品牌；提交前明确确认，响应不明保留原文件与同一操作。Worker 启动及每小时回收超过 24 小时、无引用的暂存/孤立文件与受控名称的崩溃残留；包含 Favicon 变体，失败可重试。
- **笔记 API**：已接入个人笔记分页、详情、创建、更新与删除；全部读取/写入按本人 owner 隔离，含超级管理员。写入支持版本与幂等，审计不复制标题/正文；关闭模块时不挂载接口。
- **笔记页面**：已接入本人列表/详情、筛选分页、纯文本编辑和删除确认；按当前权限显示动作，版本冲突保留草稿，响应不明保留原正文/幂等键，确认写入后的读取失败仅重读。
- **模块启停**：`pnpm ops:module -- --enable=example-notes --reason="启用参考模块"`（或 `--disable=example-notes`）显式迁移权限目录，保留笔记数据；随后同步环境开关并重启。停用移除授权，递增受影响版本、撤销会话和失效邀请；重新启用不自动恢复旧授权。
- **到期维护**：Worker 启动及每分钟通过仅限 Worker 执行的受限函数，终结过期邀请、邮箱请求和凭证，取消相关邮件并清除载荷；每批最多 100 行，状态与审计同事务。
- **操作结果查询**：`GET /api/v1/operations/:operation/:key` 按当前身份、操作权限及历史/当前目标范围查询本人 24 小时内的成功摘要；覆盖 31 种现有幂等操作。不存在、过期或越界统一 404，不返回原请求/旧 DTO，也不重新执行写入。
- **留存清理**：Worker 使用独立 maintenance 连接，启动及每小时分批清理运行记录，每天按事件时间清理审计/安全日志；邮件引用先断开再删旧凭证，保护待发邮件、有效配额和锁定状态。每批最多 1000 条，变更与计数审计同事务。
- **待完成**：正式模块裁剪/试用流程、运维恢复及其余接口，以及完整构建、部署、恢复和 P0 端到端验收。

目前可用 `pnpm start:web` / `pnpm start:worker` 分别启动服务端和邮件 Worker，`pnpm dev:server` / `pnpm dev:worker` 监听源码变化，`pnpm ops:init` 执行本机初始化。这些入口暂时使用 tsx 运行源码，需要开发依赖。执行 `pnpm build:web` 后，Web 同源提供认证页面及个人工作台。尚无完整的 `dev`、服务端编译 `build` 和生产镜像交付；`pnpm test:e2e` 会构建前端并运行 Chromium 浏览器用例。设计文档中的功能与验收指标是交付目标，不代表当前实现已全部通过验收。

## 本地开发准备

当前集成测试依赖 Linux x64 PostgreSQL 二进制，适用于 Linux x64 或 WSL Linux x64 环境，并须使用非 root 用户运行。其他平台尚未适配该测试工具。

准备 Node.js 24 和 pnpm 10.34.6，在项目根目录安装依赖：

```bash
pnpm install --frozen-lockfile
```

首次配置时，将 [.env.example](.env.example) 复制为 `.env`，已有配置时直接编辑原文件。填写自己的数据库连接、SMTP 配置、文件目录与密钥文件路径，再检查环境变量：

```bash
pnpm env:check
```

此命令校验配置格式、密钥文件及随版本分发的离线密码阻断集，不连接数据库或 SMTP。可用 `pnpm env:check -- --mode=production` 明确检查生产约束。失败时退出码为 2，仅显示配置字段名。示例中的 `replace-me` 是占位值；`.env` 和 `.local/` 已列入忽略规则。

密钥文件格式及首次生成方法见 [本地运行说明](docs/LOCAL_RUNTIME.md)。启动前需手动执行迁移；服务端只读检查迁移校验和、权限目录与模块开关，一旦不一致便拒绝启动，不自动迁移或覆盖数据库设置。

### 常用检查

```bash
# ESLint 与 TypeScript 检查
pnpm check

# 单元测试
pnpm test

# 真实 PostgreSQL 集成测试
pnpm test:integration

# 前端生产资源构建
pnpm build:web

# 首次安装测试浏览器及 Linux 依赖（需要相应系统权限）
pnpm exec playwright install --with-deps chromium

# 构建并执行真实浏览器流程
pnpm test:e2e
```

集成测试会在 `.local/tests/` 创建隔离的 PostgreSQL 17 临时集群，使用本地端口，并在正常结束时清理。无需预先启动数据库服务，也不使用 `.env` 中的业务数据库连接。测试覆盖配置、契约、权限、加密、迁移约束及事务行为；完整 P0 验收仍待完成。

### 数据库迁移

手动迁移需要事先准备 PostgreSQL 17 数据库，并在 `.env` 中设置 `MIGRATION_DATABASE_URL`：

```bash
pnpm db:migrate
```

初始迁移需要创建扩展、角色、表和授权的相应权限；请使用独立的迁移账号。迁移会建立核心结构、内建角色和权限目录，不创建用户账号或默认密码。应用数据库账号与迁移账号的权限应分开配置。

## P0 交付目标

首版围绕“初始化 → 邀请 → 授权 → 撤权 → 审计”闭环，逐步交付：

- 邮箱密码认证、邮箱验证、密码重置与会话管理。
- 个人资料、用户管理、邀请与 RBAC 权限管理。
- 管理审计、安全事件、邮件任务与系统设置。
- 文件上传、可移除的业务示例及模块接入约定。
- 配置检查、部署、迁移、备份恢复与完整验收记录。

具体规则和验收口径以 [PRD](docs/superpowers/specs/2026-10-10-honocraft-prd.md) 为准，实现细节参见 [详细设计](docs/superpowers/specs/2026-10-10-honocraft-detailed-design.md)。
