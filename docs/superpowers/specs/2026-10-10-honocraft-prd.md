## 1. 项目定位与目标

### 1.1 项目定位

HonoCraft 是面向开发者与小型团队的通用应用基础脚手架。每个部署实例服务一个企业或一个业务系统，包含多个用户、多个角色和统一管理后台，帮助团队完成认证、账号管理、授权、安全审计与基本运维，再接入自己的业务模块。

“单租户”指一个实例只有一个管理与数据域，不等于单用户。首版不引入 Tenant、Organization、Workspace、组织切换或跨租户隔离。

### 1.2 目标用户与典型场景

| 使用者 | 核心任务 | 成功结果 |
| --- | --- | --- |
| 脚手架开发者 | 初始化部署、接入业务模块、增加权限点 | 无需重新搭建身份、权限和后台基础设施 |
| 超级管理员 | 初始化系统、管理高权限账号、安全策略与委派边界 | 系统可控，可追溯，不因误操作失去管理入口 |
| 系统管理员 | 邀请成员、管理普通账号和受委派角色、排查问题 | 日常管理形成完整闭环，无需数据库人工改值 |
| 普通用户 | 注册或接受邀请、登录、维护个人资料和账号安全 | 清楚理解账号状态，能够自行完成常见操作 |
| 审计人员 | 检索安全和管理事件 | 可查明操作者、对象、结果与时间；可用自定义只读角色承载 |

主要场景：企业内部后台、私有部署应用、小型 SaaS 的单实例版本、需要用户与权限基础设施的业务系统。

### 1.3 产品目标与衡量方式

1. **完整闭环**：从首次部署到邀请成员，再到分配权限、撤销访问、查询审计，全部通过正式流程完成。
2. **授权可靠**：所有受保护接口声明访问规则；前端隐藏按钮后，直接调用接口仍受限制。
3. **安全变更有效**：账号冻结、删除、会话撤销及权限变更按明确时点生效。
4. **接入简单**：新增业务模块有文档化的权限、审计、导航和错误响应接入约定。
5. **可部署、可恢复**：提供配置说明、初始化与升级指引、备份恢复和健康检查。

验收以第 13 节场景和第 14 节交付门槛为准，不将“企业级”作为未经验证的合规或容量承诺。

### 1.4 核心使用旅程

| 旅程 | 起点与步骤 | 完成标志 |
| --- | --- | --- |
| 开发者首次使用 | 获取模板 → 配置本地依赖 → 迁移 → 捕获初始化邮件 → 设置超级管理员密码 → 登录 | 无需改业务源码或手工写数据库即可进入后台 |
| 管理员启用团队 | 邀请成员 → 成员设密并登录 → 分配普通角色 → 查看授权结果 | 成员只能访问已授予能力，邀请和角色变化可审计 |
| 开发者接入业务 | 参考示例 → 增加资源、权限和页面 → 分配测试角色 → 验证本人/他人资源边界 | 页面和直接 API 均遵守同一授权规则 |
| 管理员撤销访问 | 找到成员 → 禁用或撤销角色 → 验证旧会话 → 查审计 | 变更提交后旧会话无法继续访问，能定位操作人与结果 |
| 运维发布与恢复 | 校验配置 → 备份 → 迁移与发布 → 冒烟验证；失败时按手册恢复 | 有版本、数据与凭证失效的验证记录，不靠临场改库救场 |

## 2. 范围、优先级与交付策略

### 2.1 优先级定义

- **P0**：首个可用版本的必要能力，缺失即不具备完整管理闭环。
- **P1**：增强认证、安全和管理效率，可在 P0 稳定后交付。
- **P2**：可选扩展，按具体业务需求决定。

### 2.2 功能范围

| 模块 | P0 | P1 | P2 |
| --- | --- | --- | --- |
| 脚手架交付 | 源码模板、快速开始、配置示例、统一开发/检查/构建入口、可移除示例、模块接入文档 | 按实际重复需求增加初始化 CLI、模块生成辅助 | 插件化分发与模板市场不在当前路线内 |
| 认证 | 邮箱密码登录、可关闭的公开注册、邮箱验证、忘记/修改密码、退出 | 用户名登录、第三方 OAuth 登录与绑定 | Passkey、企业 SSO |
| 个人中心 | 姓名/昵称、头像上传、语言与主题偏好、安全入口 | 联系方式扩展 | 业务自定义资料 |
| 会话 | 当前与其他会话列表、撤销指定会话、退出其他设备、过期与撤销校验 | 可配置的长时登录、设备上限 | 风险识别与异常设备告警 |
| 用户管理 | 检索、分页、详情、资料修正、禁用/启用、软删除、发送重置邮件、角色分配 | 账号恢复、管理数据导出 | 业务定制生命周期 |
| 用户邀请 | 单个邀请、列表、重发、撤销、接受邀请 | 批量邀请、部分失败结果 | 文件导入邀请 |
| RBAC | 内建角色、自定义角色、权限目录、后端鉴权、前端权限映射、越权保护 | 更细的委派范围配置 | 行级/字段级权限、ABAC |
| MFA | 预留用户和认证流程扩展点 | TOTP、恢复码、管理员强制启用策略 | 更多认证因子 |
| 日志 | 管理审计、安全事件、登录成功/失败、过滤、详情与脱敏 | 日志导出、外部日志对接 | 风险看板、IP 地理信息 |
| 邮件 | 验证、重置、邀请与关键安全通知；失败重试与供应商受理状态 | 多语言模板管理 | 多渠道通知 |
| 配置 | 品牌信息、注册开关、普通默认角色、安全参数、配置变更审计 | 模板预览、更多策略 | 业务配置扩展 |
| 运维 | 健康/就绪检查、初始化、迁移、备份恢复指引、配置校验 | 外部监控集成 | 高可用部署示例 |
| 站内通知 | 不纳入 P0 | 按需确定 | 广播、个人通知与已读状态 |

采用已确认的分阶段交付方式：P0 先完成核心闭环，OAuth、MFA、批量邀请在 P1 增强，站内通知为可选扩展。具体功能边界及参数可在后续评审中调整，并同步修订验收标准。

### 2.3 明确不包含

- 多租户、组织树、部门、企业切换、跨租户共享与隔离。
- 订阅套餐、支付、账单、订单、额度和商业计费。
- 股票研究、电商、CRM 等行业业务。
- 通用工作流引擎、插件市场、自动审批系统。
- 首版业务 API Key、机器账号及对外开放平台。
- 基于角色自动推导的行级数据隔离。业务资源的归属校验仍需由业务模块实现。

### 2.4 可选产品方向比较

| 方向 | 优点 | 成本与限制 | 本文选择 |
| --- | --- | --- | --- |
| 分阶段的通用后台 | 核心闭环清晰，依赖少，易复用 | OAuth/MFA 等分批交付 | 用户已确认 |
| 原稿全部功能一次交付 | 首版能力较全 | 身份绑定、MFA 恢复、批量发送等明显增加验证范围 | 本轮未选择 |
| 扩展为完整商业 SaaS 平台 | 包含租户与计费能力 | 偏离原始目标，扩大架构和运维复杂度 | 不纳入 |

## 3. 全局业务规则与建议默认值

### 3.1 身份与唯一性

1. P0 使用邮箱作为唯一登录标识，用户 ID 为稳定身份；邮箱不是业务外键。
2. 产品将邮箱定义为不区分大小写：去除首尾空白并统一大小写用于唯一性比较；保留展示值。不自动删除 `+tag` 或邮箱中的点。
3. 已软删除账号的邮箱仍占用唯一性，P0 不允许重新注册或邀请；避免历史归属混淆。恢复与最终清理属于后续能力。
4. 昵称不唯一，不能用于登录。用户名登录若在 P1 启用，需另定义独立唯一用户名和与邮箱输入的识别规则。
5. 所有权限由后端计算，客户端提交角色、账号状态或权限字段不能改变其自身身份。

### 3.2 建议默认参数

| 参数 | 建议值 | 配置与约束 |
| --- | --- | --- |
| 公开注册 | 默认关闭 | 超级管理员可开启；不影响正常邀请与已有用户登录 |
| 注册默认角色 | `user` | 只能选择已标记为“允许自助注册分配”的普通角色，不能包含管理权限 |
| 邮箱验证有效期 | 24 小时 | 可配置 1–48 小时 |
| 密码重置有效期 | 30 分钟 | 可配置 10–60 分钟 |
| 邀请有效期 | 72 小时 | 可配置 1–168 小时 |
| 邮件发送冷却 | 同一目标与用途 60 秒 | 每地址每用途每小时最多 5 次；每来源 IP 每小时最多 20 次 |
| 登录保护 | 每来源 IP 每分钟最多 20 次尝试；每账号 15 分钟内失败 5 次后暂锁 15 分钟 | 暂锁属于认证保护，不改变账号业务状态；成功完整认证后清除失败计数 |
| 会话期限 | 空闲 30 分钟，绝对 8 小时 | 两者均由服务端检查；绝对期限不因活跃而延长 |
| 近期身份验证 | 5 分钟 | 修改密码/邮箱、提权等高风险操作需要；不依赖页面是否一直打开 |
| 自定义角色 Code | 3–64 位小写字母、数字、`_` 或 `-`，以字母开头 | 不可使用内建 Code；创建后不可修改 |
| 密码长度 | 15–128 个字符 | 支持空格与 Unicode，按码点计数；禁止静默截断，不强制字符组合或周期换密 |
| 列表分页 | 默认 20 条，最大 100 条 | 服务端限制，采用稳定排序 |
| 头像 | JPEG / PNG / WebP，最大 2 MB | 校验实际文件内容并重新编码；不接受 SVG 和任意外链抓取 |
| 登录/安全日志保留 | 90 天 | 管理审计默认 180 天；部署者可按自身政策调整 |
| 时区 | 存储 UTC | 展示使用实例配置时区；默认 UTC，支持配置为 Asia/Tokyo 等时区 |

以上数值用于建立可测试的基线，不是标准强制值。配置修改须校验范围，并保留至少一种可用管理与认证路径。发送配额统计用户触发的发送/重发请求，后台投递重试计入任务尝试次数；关键安全通知单独限流与去重，不能因重置邮件额度耗尽而直接丢弃。非公开入口也不能绕过发送保护。

## 4. 认证、账号安全与个人中心

### 4.1 公开注册与邮箱验证（P0）

**输入**：邮箱、密码、姓名/昵称；确认密码仅用于客户端辅助检查，后端独立校验密码策略。

**流程与规则**：

1. 注册开关关闭时隐藏入口，服务端拒绝新建公开注册请求。已有 Pending 用户仍可完成验证。
2. 注册开关开启且输入有效时，新建 Pending 用户并安排发送验证邮件；默认角色在创建时记录。
3. Pending 用户只能进入验证引导与重发流程，不能建立访问业务系统的正式会话。
4. 提交有效验证凭证后，原子地消费凭证、标记邮箱已验证并激活账号；随后进入登录页。提交时重新检查用户仍为 Pending 且创建时记录的默认角色仍满足自助分配约束；失效时拒绝激活并引导管理员处理，不自动替换为其他角色。
5. 链接过期、撤销、用途不匹配或已消费时不产生重复副作用，提供重新发送入口。
6. 重发生成新凭证并使旧凭证失效；邮件链接的 GET 访问不消费凭证，防止邮件扫描器提前使用。
7. 对有效格式的重复邮箱与新邮箱返回一致的受理提示，不公开账号是否存在；内部决定是否发送邮件，且仍受限流。
8. 注册提交后邮件供应商异常不得删除已创建用户；界面说明已受理，用户可稍后重发。

### 4.2 邮箱密码登录（P0）

- 验证邮箱、密码、账号状态与临时锁定；所有条件通过才创建正式会话。
- 不存在的账号、密码错误、业务禁用或软删除使用相同的公开失败提示；详细原因写入内部安全日志。
- 只有凭证正确且账号为 Pending 时，允许显示待验证引导；仍不授予业务权限。
- 登录失败不得写入密码、完整认证请求或验证凭证。不存在用户时用脱敏目标标识记录，不建立伪用户。
- 成功登录更新最后登录时间并记录事件。会话建立必须使用新的随机凭证，不能沿用登录前标识。
- 退出同时撤销服务端会话并清除客户端凭证，重复退出不产生错误副作用。

### 4.3 忘记密码与修改密码（P0）

| 操作 | 前置条件 | 成功行为 |
| --- | --- | --- |
| 请求找回密码 | 无需登录；符合格式与限流 | 统一提示“若账号可用，将发送邮件”；仅对邮箱已验证的 Active 本地密码账号生成凭证 |
| 使用重置链接 | 凭证有效、一次性、用途正确；提交时账号仍可用 | 设置新密码，消费全部未用重置凭证，撤销所有会话，通知用户，返回登录页 |
| 修改密码 | Active 会话，校验原密码，新密码符合策略 | 更新密码并撤销所有会话，要求重新登录，通知用户 |
| 管理员触发重置 | 有 `user:reset-password`，目标在可管理范围且为 Active、邮箱已验证 | 发送重置邮件，记录审计；仅发送请求不会修改密码或冻结账号 |

不生成、展示或邮件发送临时明文密码；管理员也不能读取或指定用户的新密码。已禁用/删除的账号不能通过重置密码恢复访问。密码重置不替代 MFA 验证或关闭 MFA。

### 4.4 个人资料（P0）

- 允许本人更新昵称、姓名和头像；姓名/昵称为 1–80 个字符，按纯文本渲染。
- 头像上传通过文件类型、大小和内容验证；去除不必要元数据，使用系统生成文件名，业务失败不留下无限孤立文件。
- 支持中文与英文、浅色/深色/跟随系统主题。偏好保存在用户资料中，无偏好时使用实例默认值。
- 联系电话等字段在 P1 按需增加，不默认承担短信验证能力。
- 修改邮箱必须通过独立流程，不允许通用个人资料接口直接更新登录邮箱。

### 4.5 邮箱变更（P0）

1. 本人经近期身份验证，或管理员经近期身份验证、有 `user:update-email` 且目标在可管理范围，提出新邮箱。
2. 校验新邮箱唯一性并发送新邮箱验证邮件；原邮箱继续作为有效登录标识，数据库保留待变更邮箱。
3. 新邮箱验证成功时再次检查唯一性、账号状态及请求仍为最新有效版本；管理员发起的请求还须检查该管理员仍可管理目标。在同一事务完成替换、消费凭证、撤销全部会话与其他指向旧邮箱的未消费凭证；已有待发送旧凭证任务取消，必要的原邮箱安全通知保留。
4. 原邮箱收到变更发起与完成通知；通知不包含敏感凭证。
5. Pending 账号由管理员修正邮箱也创建待变更请求，原地址在验证前继续占用，旧注册验证凭证撤销；验证新地址后才替换邮箱并按第 4.1 节检查角色后激活。未完成变更前保持 Pending，不因管理员修正直接激活。
6. 过期、冲突或取消不替换原邮箱。原邮箱无法接收邮件的账号恢复由部署者人工核实，不自动绕过新邮箱验证。
7. 每名用户最多有一项有效变更请求；新请求替换旧请求并使旧链接失效。本人或仍有管理资格的发起者可取消请求，失败和取消均保留审计。新邮箱在验证前不作为登录标识，也不永久预占唯一性。

### 4.6 近期身份验证（P0）

- 验证的是当前操作者本人；P0 重新校验当前密码，成功后记录当前会话的 `reauthenticated_at`。其他设备会话不能共享该结果。
- 修改密码必须在本次操作校验原密码；邮箱变更、授予/撤销高权限角色、处理高权限账号、修改注册/安全策略需在 5 分钟有效窗口内完成。
- 缺少近期验证时返回 403 与 `REAUTH_REQUIRED`，前端完成验证后让用户重新确认原操作；不自动重放删除、提权等写请求。
- 重新验证失败受认证限流约束，失败不能刷新时间戳；普通页面活跃也不能刷新。P1 引入 OAuth/MFA 后必须定义等效的重新验证流程，并满足已启用的 MFA 要求。

### 4.7 OAuth 登录与身份绑定（P1）

- 首批建议支持 Google 与 GitHub，最终平台清单取决于使用场景与部署可用性；未配置完整的供应商不显示入口。
- 外部身份以 `(provider, provider_subject)` 唯一识别，不以邮箱自动合并本地账号。
- 首次外部登录创建账号仍受注册策略约束；邀请专用模式下必须先完成有效邀请。
- 未提供可验证邮箱的供应商身份，必须完成本系统邮箱验证后激活。
- 绑定已有账号必须在其正式会话内，经近期身份验证后完成 OAuth 验证；相同邮箱本身不是绑定授权。
- 解绑要求保留至少一种可用登录方式；密码为空的外部身份账号要先验证邮箱并设置密码，再移除最后一个外部身份。
- 回调校验授权状态、重定向地址与协议所需安全参数；身份验证失败不能建立会话。
- 禁用/删除状态优先于 OAuth 成功结果。邮箱相同但未绑定时引导登录原账号后绑定，不静默创建第二个用户或接管账号。

### 4.8 MFA（P1）

- TOTP 绑定必须先完成近期身份验证；只有用户成功提交测试验证码后才启用。
- 显示一次性恢复码，服务端仅保存其哈希；每个恢复码仅可使用一次。
- 密码或 OAuth 验证成功后先建立短期、受限认证事务；MFA 验证完成前不得创建正式业务会话。
- 关闭 MFA、更换设备和重新生成恢复码要求近期身份验证及现有因子或有效恢复码。
- 验证器密钥需要加密存储，不进入日志或普通用户响应；同一时间步的成功验证码不得重放。
- 可启用管理员强制 MFA，提供配置后的宽限期与明确引导；超过期限未绑定者只能访问安全设置，不能执行管理操作。
- 丢失全部因子的恢复走部署者身份核实流程，撤销会话、记录审计并通知用户；普通管理员不能直接绕过他人 MFA。

## 5. 会话管理（P0）

### 5.1 会话列表与操作

列表展示设备类别、浏览器/操作系统、登录时间、最近活跃时间、来源 IP、是否当前会话。设备信息由 User-Agent 尽力识别，无法判断时展示“未知”，不承诺获取真实设备型号。IP 不等于唯一设备身份。

- 本人可撤销指定会话或“退出其他所有设备”，仅能操作自己的会话。
- 撤销当前会话立即回到登录页；退出其他设备保留当前会话。
- 已过期或已撤销的会话不出现在活跃列表中，必要历史保留在安全日志。
- 最近活跃时间允许最多 60 秒的展示延迟；这不影响撤销和过期校验。

### 5.2 生效时点

| 事件 | 账号/会话行为 |
| --- | --- |
| 禁用或软删除 | 操作提交成功时撤销目标全部会话；后续请求不得获得业务访问 |
| 主动撤销会话 | 提交成功后该会话的下一次受保护请求拒绝 |
| 密码重置、修改密码、邮箱替换 | 全部会话撤销，重新登录 |
| 用户角色变更、角色权限变更 | 相关用户的授权版本更新并撤销旧会话；重新登录获取新权限 |
| 启用已禁用用户 | 不恢复旧会话，要求重新登录 |
| 会话到期 | 服务端拒绝；前端清理身份状态并返回登录页 |

权限变化不能仅依赖旧 Token 过期。受保护请求必须确认会话仍有效、账号可用及授权版本匹配。已经提交成功的业务行为不追溯撤销；高风险写操作应在事务提交前再次校验状态/授权版本，防止检查后发生撤权仍执行。

### 5.3 客户端凭证约束

Web 默认使用服务端可撤销会话，以具备 HttpOnly、Secure 属性的 Cookie 传递，结合 SameSite、来源校验及适用的 CSRF 防护。具体会话库和是否支持独立 API 客户端留到技术设计确定。

## 6. 用户管理与邀请

### 6.1 用户状态

| 状态 | 含义 | 可进行的主要动作 |
| --- | --- | --- |
| Pending | 已公开注册，邮箱尚未验证 | 完成验证、重发验证、管理员修正/禁用/删除 |
| Active | 已激活且未禁用 | 登录、维护个人资料、在授权范围内访问 |
| Suspended | 业务禁用 | 拒绝业务访问；管理员按权限启用或删除 |
| Deleted | `deleted_at` 有值的软删除账号，在界面表现为独立状态 | 拒绝登录与再次注册；P0 仅只读查阅 |

转换规则：

- 公开注册 → Pending；有效邮箱验证 → Active。
- 新账号接受有效邀请并设置密码 → Active；无需再次验证同一邀请邮箱。
- Pending / Active → Suspended，同时撤销会话和未消费的验证、重置、邮箱变更凭证。
- Suspended → Active 或 Pending，依据 `email_verified_at` 判断；不凭“启用”跳过邮箱验证。
- Pending / Active / Suspended → Deleted；撤销会话、清除用户角色关联、取消相关未完成邀请和一次性凭证，历史日志保留。
- Deleted → 原合法状态的恢复为 P1，恢复后重新配置角色，不能复活旧会话和凭证。

临时登录锁定是独立的 `locked_until`，不与 Suspended 混用。邀请未接受时只创建 Invite，不预创建 Pending 用户，避免状态语义混乱。

### 6.2 用户列表与详情

- 支持姓名/昵称、邮箱模糊搜索；按状态、角色、创建时间范围筛选。
- 默认按创建时间倒序并以 ID 保证稳定排序；显示总数、分页和当前筛选。
- 列表字段：头像、姓名/昵称、邮箱、角色、状态、创建时间、最后登录时间、可用操作。
- 详情展示基本资料、角色、邮箱验证状态与审计入口；不展示密码哈希、会话凭证、MFA 密钥。
- Deleted 默认隐藏，可通过明确筛选查看。空结果、加载失败、无权限与空数据库采用不同提示。

### 6.3 管理操作

| 操作 | 规则 |
| --- | --- |
| 新增用户 | P0 统一走邀请，不直接创建管理员已知密码的账号 |
| 修改资料 | 仅修改允许字段；邮箱走独立验证流程；角色、状态不能混入资料更新 |
| 禁用/启用 | 二次确认并记录原因；禁止管理者禁用自己；受第 7 节管理范围保护 |
| 软删除 | 展示影响说明和目标邮箱，输入确认；不级联删除未来业务历史数据 |
| 发送密码重置 | 仅对可用本地密码账号操作；受发送限流，不返回密码或重置链接 |
| 分配角色 | 在可授予范围内新增/替换/移除；显示权限变化摘要，角色字段整体更新要防并发覆盖 |

普通用户可以暂时没有角色，此时只能访问本人资料和安全设置。超级管理员账号可变更的前提见第 7.2 节。

### 6.4 单个邀请（P0）

**输入**：邮箱、一个或多个初始角色。默认 `user`，不得为空；可授予角色由服务端校验。

1. 检查操作者具备 `invite:manage`，目标角色有效且在其可授予范围内。
2. 目标已存在任何状态的用户时，不发送“注册邀请”；提示转到已有账号的对应管理流程，不通过邀请合并身份或新增角色。
3. 相同规范化邮箱最多有一个有效 Pending 邀请；重复点击或请求重试不创建多份邀请。
4. 建立邀请与待发送任务后返回“已受理”；邮箱发送失败仍保留邀请，可重试。
5. 接收者打开链接查看系统名称、受邀邮箱和有效期，提交密码与昵称时再次验证邀请。
6. 在同一事务中创建已验证的 Active 用户、绑定约定角色并消费邀请；完成后去登录页。
7. 并发接受仅一次成功。提交时若邮箱已被注册、角色已不可分配、角色版本与发出邀请时不同，或邀请人失去邀请/授予资格，则不创建用户，提示联系管理员处理或重发；不能按已悄悄扩大的角色权限激活账号。
8. 邀请链接 GET 不执行激活；实际提交才消费凭证。不能通过请求参数修改受邀邮箱或角色。

### 6.5 邀请状态、重发与撤销

| 状态 | 含义 | 操作 |
| --- | --- | --- |
| Pending | 未接受且仍在有效期 | 重发、撤销 |
| Accepted | 已成功创建账号 | 查看；不可重发或撤销以删除账号 |
| Expired | 超过有效期 | 重新邀请；旧链接保持失效 |
| Revoked | 被撤销或因资格变化主动撤销 | 重新邀请；旧链接保持失效 |

- 重发替换凭证并重置期限，重新校验角色可授予范围并记录当前角色版本；旧链接立即失效，角色修改也必须重新发送。
- “邮件发送成功”与“邀请已接受”分别记录；服务商受理不等于用户收到或打开邮件。
- 邀请人被禁用/删除时，相关 Pending 邀请撤销；删除角色须先显式撤销相关邀请，再解除用户引用，仍有引用时拒绝删除，不由删除操作隐式撤销。权限范围变化在接受时重新检查。
- 列表支持邮箱、状态、邀请人、时间筛选，展示邀请人、角色、有效期和邮件发送状态。

### 6.6 批量邀请（P1）

- 单批最多 100 个邮箱，先去重和校验；有效目标逐项处理，不因一个失败全部回滚。
- 返回每项结果：已受理、重复、已有账号、格式错误、角色不可授予、发送失败等；允许仅重试失败项。
- 使用批次 ID 追踪，沿用单邀请安全规则和发送配额；邮件异步发送，提供整体进度。

## 7. RBAC、管理范围与权限目录

### 7.1 授权模型

- 用户与角色多对多，角色与权限多对多。用户有效权限为全部已分配角色权限的并集。
- P0 不支持用户直接授予权限、不支持显式 Deny、不建立自定义角色上下级。
- 页面、菜单、按钮映射到同一权限 Code；后端为最终执行边界，不依赖前端鉴权结果。
- “本人资料/会话”采用服务端本人校验，客户端传入其他用户 ID 不能绕过。
- 业务开发者新增资源时，必须同时声明功能权限和必要的资源归属检查；`order:read` 本身不定义可见哪些订单。
- 未显式声明公开、本人访问或权限要求的业务接口默认拒绝；健康检查等公开例外列入清单。

### 7.2 内建角色与保护

| 角色 | 默认职责 | 保护与委派规则 |
| --- | --- | --- |
| `super_admin` | 全部已注册权限，初始化与高权限管理 | 角色不可删除、改 Code 或缩减权限；新增注册权限自动纳入；账号操作遵守最后一名保护 |
| `admin` | 普通用户管理、邀请、受委派角色维护、常规设置与日志查看 | 不可管理拥有 `admin` / `super_admin` 的账号；不能授予这两个角色或受保留权限 |
| `user` | 本人资料与安全能力，未来业务基础权限 | 内建普通角色，默认可委派且可用于注册；无后台管理权限；内建角色不可删除 |

**超级管理员账号保护的建议调整**：保护“至少一名 Active、邮箱已验证、拥有可用认证方式的超级管理员”，而不是永久禁止任何超级管理员账号被禁用或删除。其他超级管理员在满足此条件时可以被撤权、禁用或删除，便于人员离职与安全处置。

- 禁止管理者通过后台修改自己的角色、禁用或删除自己；本人可修改个人资料与安全设置。
- 仅超级管理员可授予/撤销 `super_admin`、`admin`，操作要求近期身份验证、二次确认与审计。
- 检查最后一名保护必须与变更在同一事务完成，防止两名管理员并发互相撤权留下零管理员。
- 若 P1 启用强制 MFA，“可用认证方式”还须满足相应 MFA 策略。

### 7.3 防止间接提权

1. 系统管理员只能分配标记为“可委派”的角色；这些角色内全部权限必须属于权限目录中的可委派项，且同时是其当前拥有的权限。管理其他低权限账号已持有的角色时也检查该边界。
2. 保留权限包括高权限账号管理、安全策略、注册默认角色策略、审计清理与认证提供商/密钥配置；不能加入管理员可维护的自定义角色。
3. 系统管理员不能修改或删除分配给任何 `admin` / `super_admin` 账号的角色，也不能修改自身持有的角色。
4. 管理员可以变更的账号必须同时满足操作权限与目标范围检查，不能通过替换全部角色、修改邮箱或重置密码接管高权限账号。除排除内建高权限角色外，目标当前持有的全部角色及权限也必须在操作者可委派范围内；持有保留权限或不可委派角色的自定义角色账号同样受保护。拥有 `user:read` 的管理员可读取脱敏高权限账号资料，但读取不授予任何变更权限。
5. 如果分配操作将使受管理目标获得超出操作者可委派范围的权限，应整体拒绝，而不是悄悄部分分配。
6. 高权限管理和默认注册角色等保留事项由超级管理员执行；自定义角色的可委派资格由超级管理员设置。权限是否可委派由版本化目录定义；保留权限始终不可委派，后台不能将其改为普通权限。
7. 上述限制适用于所有非超级管理员，即使其管理能力来自自定义角色。是否可委派、是否可自助注册分配是两种独立资格；有前者不代表有后者。
8. 权限目录使用独立的 `is_self_assignable` 标记，默认关闭；所有用户/角色/邀请/日志/系统配置管理权限始终禁止自助分配。注册默认角色必须标记 `is_registration_default_eligible`，且只包含可自助分配的权限；该资格仅超级管理员可配置。
9. 修改被选为注册默认角色或被 Pending 用户持有的角色时，必须保持上述普通权限约束；不允许先设默认角色、再加管理权限。改变默认角色配置只影响之后创建的账号；旧 Pending 用户激活时仍检查原分配角色。版本升级新增权限也须遵守此约束。

### 7.4 角色管理

- 自定义角色支持创建、修改、复制、删除；Code 在创建后不可修改，唯一且符合命名规则。
- 内建角色不支持删除；其权限基线来自版本化权限目录，变更须经过正式版本升级。
- 复制仅生成新的自定义角色草稿，仍检查可授予范围，不复制内建身份或保护属性；新角色的可委派、自助分配资格默认均关闭，由超级管理员独立设置。
- 删除角色前必须解除所有用户关联并处理 Pending 邀请；仍被引用时返回冲突，不静默迁移用户。
- 配置权限时显示模块分组、说明与所需前置权限；例如 `user:delete` 要求同时具备 `user:read`，缺少时阻止保存。
- 编辑采用版本校验，旧页面保存返回冲突并提示刷新，避免覆盖别人刚做的变更。

### 7.5 首版权限目录

| 权限 Code | 控制内容 | 默认 Admin | 属性 |
| --- | --- | --- | --- |
| `user:read` | 用户列表与详情 | 有 | 可委派 |
| `user:update` | 普通资料修正 | 有 | 可委派，依赖 `user:read` |
| `user:update-email` | 发起邮箱变更 | 有 | 可委派，依赖 `user:read`；受目标范围限制 |
| `user:change-status` | 禁用/启用 | 有 | 可委派，依赖 `user:read` |
| `user:delete` | 软删除 | 有 | 可委派，依赖 `user:read` |
| `user:reset-password` | 发送重置邮件 | 有 | 可委派，依赖 `user:read` |
| `user:assign-role` | 分配普通角色 | 有 | 可委派，依赖 `user:read`、`role:read` |
| `user:manage-privileged` | 操作管理员、授予/撤销高权限角色 | 无 | 保留；仍需具体操作权限 |
| `invite:read` | 查看邀请 | 有 | 可委派 |
| `invite:manage` | 创建/重发/撤销邀请 | 有 | 可委派，依赖 `invite:read`、`role:read` |
| `role:read` | 查看角色 | 有 | 可委派 |
| `role:manage` | 创建/编辑/复制/删除自定义角色 | 有 | 可委派，依赖 `role:read`、`permission:read`；受角色范围限制 |
| `role:delegate` | 设置自定义角色的委派资格 | 无 | 保留；不能改写权限目录的保留属性 |
| `permission:read` | 查看已注册权限目录 | 有 | 可委派 |
| `audit:read` | 查看脱敏管理审计 | 有 | 可委派 |
| `security-log:read` | 查看脱敏登录/安全日志 | 有 | 可委派 |
| `email-task:read` | 查看邮件任务状态、尝试次数与脱敏错误 | 有 | 可委派；不返回凭证与完整邮件载荷 |
| `settings:read` | 查看无密钥配置 | 有 | 可委派 |
| `settings:update-branding` | 修改品牌和展示设置 | 有 | 可委派，依赖 `settings:read` |
| `settings:update-security` | 修改注册、安全、默认角色策略与角色自助分配资格 | 无 | 保留，依赖 `settings:read` |

本人资料、修改密码和本人会话管理不通过上述管理权限授予。所有自定义角色默认仅能由超级管理员配置可委派标记。

权限目录由业务代码/模块声明并在部署时同步，不提供在后台随意新增任意字符串的能力。权限删除或重命名必须有迁移说明，不能产生绕过或自动扩大授权。

## 8. 审计、邮件、系统设置与运行能力

### 8.1 管理审计（P0）

必须覆盖：用户资料和邮箱变更、禁用/启用/软删除、重置邮件触发、角色分配、角色与权限修改、邀请创建/重发/撤销、系统设置修改、超级管理员初始化及后续高权限操作。

记录字段：事件 ID、时间、操作者类型与 ID、操作者展示快照、Action、目标类型与 ID、结果、拒绝/失败原因编码、来源 IP、简化 User-Agent、request_id、脱敏变更摘要、操作者填写的原因。

- 审计关联动作与目标，不要求依附某个会话；初始化、后台任务和匿名事件也能记录。
- 变更快照只收集允许字段，禁止整个请求/用户实体直接序列化。
- 禁止保存密码、密码哈希、Cookie、原始 Session、Token、OAuth 凭证、TOTP 密钥、恢复码和邮件完整敏感链接。
- 修改成功的管理审计与业务变更保持事务一致；审计写入失败时高风险变更不得返回成功。
- 拒绝或失败的操作记录独立事件；不因失败事务回滚丢失全部证据。
- 后台只有查询能力，无编辑/删除入口。留存到期由受控后台任务清理，清理任务另记事件；不宣称提供不可篡改取证存储。
- 支持操作者、动作、对象、结果和时间过滤，查看详情。导出属 P1，需单独权限并记录导出事件。

### 8.2 登录与安全日志（P0）

记录登录成功/失败、认证限流、会话创建/撤销、密码重置完成、邮箱变更完成、权限版本变化及异常凭证使用。P1 增加 MFA、身份绑定等事件。

IP 地址按可信代理配置提取，不能直接相信客户端自报的转发头。IP 地理位置属于 P2；未知位置不能当作异常结论。密码等敏感值同样禁止写入应用日志与错误追踪。

### 8.3 邮件任务与发送结果（P0）

- 模板包括邮箱验证、密码重置、邀请、密码变更通知、邮箱变更通知、账号禁用通知；P1 增加 OAuth/MFA 安全变更通知。
- 至少接入一种可实际使用的发送方式；开发环境提供邮件捕获方式，不能把生产邮件发到真实用户作为默认测试。
- 业务事务创建持久化发送任务，不在请求内等待外部邮件服务；使用事件 ID/幂等键防止普通重试重复建任务。
- 状态为 Queued / Sending / Sent / Failed / Cancelled；Sent 表示供应商受理，不承诺投递到收件箱。
- 默认最多 3 次发送尝试，间隔约 1 分钟、5 分钟；可重试失败且未耗尽次数时回到 Queued，永久失败或次数耗尽才进入 Failed。凭证已失效或用途取消时进入 Cancelled，停止重试。
- Sending 任务必须设置有期限的领取租约；进程崩溃后到期可重新领取，不能永久卡住。并发领取不允许正常情况下重复执行同一任务；供应商超时等不确定结果按下述重复投递边界处理。
- 邮件任务中的敏感链接载荷加密保存，并在无需重试或过期后删除；身份凭证表仅保存 Token 哈希，不能为发送便利保存其明文。
- 重发产生新的凭证任务；旧任务被取消或发送前检查版本，避免主动发出已被替换的链接。
- 供应商超时可能产生重复投递，系统不宣称跨供应商“恰好一次”；同一凭证重复投递仍只能成功消费一次。
- 运维可见邮件任务状态和错误摘要，不能从普通后台读取邀请/重置 Token。
- P0 后台提供只读任务列表，可按用途、状态、时间检索；最终失败的验证、重置、邀请由原流程重发，仍需当前权限及配额校验。安全通知保留失败记录供运维处置；P0 不提供通用后台强制重放入口。

### 8.4 系统配置（P0）

| 配置类型 | 范围 | 管理方式 |
| --- | --- | --- |
| 品牌与展示 | 名称、Logo、Favicon、版权、默认语言/主题/时区 | 有常规配置权限的管理员 |
| 注册与角色 | 公开注册开关、普通默认角色 | 超级管理员 |
| 安全策略 | 会话期限、验证/邀请期限、密码最低长度、锁定与发送限流 | 超级管理员；禁止弱化到低于产品最低约束 |
| 部署密钥 | 数据库、邮件服务凭证、签名/加密密钥、OAuth Secret | 部署环境或密钥配置，不作为普通后台可读/可写设置 |

配置保存按整组校验，失败时保留原值。更新立即对新请求/新任务生效；缩短会话期限也对现有会话按原创建/活跃时间重新计算。一次性凭证的有效期在签发时固定，策略修改不延长旧凭证。

### 8.5 初始化与恢复（P0）

- 首次部署通过仅部署者可执行的初始化流程创建第一名超级管理员，不开放可抢注的公共初始化接口。
- 不提供固定默认密码；初始化要求验证目标邮箱并设置密码，成功后初始化入口永久关闭或幂等拒绝再次创建。
- 初始化邮件失败可由部署者重发；初始化完成前仍允许诊断健康状态，但不能开放业务系统。
- 提供超级管理员失联时的受控恢复步骤：身份核实、生成短期一次性设置凭证、撤销旧会话、记录事件；不提供公网“恢复万能密码”。
- 恢复流程只描述所需操作与审计责任；具体脚本、命令和密钥管理在技术设计中明确。

### 8.6 健康检查与运行信息（P0）

- 存活检查用于确认进程可响应；就绪检查确认数据库、必要迁移和配置可用。
- 邮件短暂不可用时核心系统仍可就绪，但报告内部依赖降级并保留待发任务。
- 公开端点仅返回最小状态，不暴露数据库地址、密钥、详细错误或用户数据。
- 应用日志为结构化格式，携带 request_id，允许按请求关联排障。
- 提供备份恢复、版本升级、密钥轮换与运行故障说明；数据库迁移记录版本且禁止运行在未知不兼容结构上。

## 9. 信息架构与交互要求

### 9.1 页面结构

| 页面组 | 页面 | 可见范围 |
| --- | --- | --- |
| 认证 | 登录、注册、验证引导/结果、忘记密码、重置密码、接受邀请 | 未登录可达；按注册策略与凭证限制 |
| 应用首页 | 欢迎信息、可访问模块入口 | Active 用户；无业务权限时引导个人中心 |
| 个人中心 | 基本资料、安全设置、会话、偏好 | 本人 |
| 用户管理 | 用户列表、详情、资料编辑、状态操作、角色分配 | 对应管理权限 |
| 邀请管理 | 邀请列表、新建、重发、撤销 | 对应邀请权限 |
| 角色权限 | 角色列表、详情/编辑、权限目录 | 对应角色管理或权限目录读取权限 |
| 日志 | 管理审计、登录/安全日志、详情 | 对应日志读取权限 |
| 邮件任务 | 状态列表、失败摘要与任务详情 | `email-task:read`；不展示敏感载荷 |

P1 增加 OAuth 绑定/MFA 页面与批量邀请进度；P2 站内消息等入口不预先占用首版菜单。

### 9.2 通用交互

- 列表统一搜索、筛选、分页；筛选条件在分页时保留。
- 提交操作提供加载状态并防重复点击；成功后更新列表，失败保留输入并说明可采取的动作。
- 权限不足展示 403 页面；会话失效返回登录，成功后可回到允许的站内路径，不接受任意外部跳转地址。
- 禁用、删除、角色提权与安全策略修改需明确目标和影响的二次确认；删除及高权限变更增加目标输入确认。
- 桌面完成全部管理流程；移动端至少完成认证、个人中心、会话与用户查询，表格采用卡片或可控横向滚动。
- 支持键盘操作、可见焦点、表单标签与错误关联，状态不只用颜色区分；以 WCAG 2.2 AA 作为验证目标。
- 全部界面文案使用翻译键，P0 的中文/英文覆盖认证、错误信息、管理页面和邮件。
- 前端收到 `REAUTH_REQUIRED` 时打开当前操作者的重新验证界面；收到版本冲突时保留本次输入并提示刷新比较，不静默覆盖。

## 10. 概念数据模型与一致性约束

本节描述业务实体及约束，不替代数据库物理设计；ID 类型、索引和存储方案在技术设计中确定。

| 实体 | 主要字段 | 关键约束 |
| --- | --- | --- |
| User | id、email、normalized_email、password_hash（可空）、display_name、avatar_key、status、email_verified_at、locked_until、authorization_version、preferences、created_at、last_login_at、deleted_at、version | 邮箱全局唯一；Deleted 为逻辑删除状态；外部身份账号密码可空 |
| Role | id、name、code、description、is_builtin、is_delegable、is_registration_default_eligible、version | Code 唯一且不可修改；内建角色保护；注册资格与委派资格分离 |
| Permission | id、code、name、module、description、is_reserved、is_delegable、is_self_assignable、dependencies | Code 唯一，来自版本化模块目录；保留权限不可委派，管理权限不可自助分配，后台不能改写目录属性 |
| UserRole | user_id、role_id、assigned_by、assigned_at | 组合唯一，外键有效 |
| RolePermission | role_id、permission_id | 组合唯一；保存时检查依赖完整性 |
| Session | id、user_id、token_hash、authorization_version、created_at、last_seen_at、reauthenticated_at、idle_expires_at、absolute_expires_at、revoked_at、ip、user_agent | 多个会话属于一个用户；服务端检查状态与版本；近期验证只对本会话有效；不保存明文 Token |
| OneTimeCredential | id、user_id（可空）、invite_id（可空）、purpose、target_email、token_hash、expires_at、consumed_at、revoked_at | 用途分离、一次性消费；用于验证、重置、邮箱变更和邀请 |
| Invite | id、email、normalized_email、inviter_id、status、expires_at、accepted_by、accepted_at、created_at、version | 同一邮箱最多一个有效邀请；Accepted 不可重发 |
| InviteRole | invite_id、role_id、role_version_at_issue | 邀请可分配多个角色；接受前重新检查角色版本与授予资格 |
| EmailChangeRequest | id、user_id、requested_by、new_email、normalized_new_email、status、expires_at | 当前有效变更最多一项；验证时再次检查邮箱唯一性 |
| AuditEvent | id、actor_type、actor_id（可空）、actor_snapshot、action、target_type、target_id、result、reason_code、changes、request_id、ip、created_at | 对应操作/目标，不依赖 Session；展示快照经过脱敏 |
| SecurityEvent | id、user_id（可空）、event_type、result、reason_code、target_digest、request_id、ip、user_agent、created_at | 匿名失败可记录；目标摘要用于关联但不公开 |
| EmailTask | id、event_key、purpose、recipient、encrypted_payload、status、attempts、next_attempt_at、lease_owner、lease_expires_at、provider_message_id、error_code、created_at | 事件幂等；领取租约可恢复；载荷按生命周期清理 |
| SystemSetting | key、typed_value、version、updated_by、updated_at | 类型与范围校验；不保存部署密钥 |
| ExternalIdentity（P1） | id、user_id、provider、provider_subject、provider_email、linked_at | `(provider, provider_subject)` 唯一；邮箱不代表绑定关系 |
| MfaFactor / RecoveryCode（P1） | user_id、type、encrypted_secret、verified_at、code_hash、used_at | 恢复码一次性；密钥加密 |

**关联摘要**：User 1:N Session；User N:M Role；Role N:M Permission；Invite N:M Role；User 1:N ExternalIdentity；AuditEvent 关联操作者与任意目标。审计日志与 Session 不形成原稿中的强制链式依赖。

**一致性要求**：

- 邮箱唯一性、有效邀请唯一性与一次性消费由数据库/事务约束保证，不能仅依赖“先查询再插入”。
- 用户状态、角色关系、授权版本与成功审计共同提交；角色权限变更同步影响所有关联用户的授权版本与会话。
- 邀请接受的用户创建、角色绑定、凭证消费及邀请状态更新共同提交。
- 业务实体引用稳定 User ID，软删除不级联删除业务记录；用户恢复/最终删除策略须由业务模块明确。
- 展示时间转换不修改事实时间；清理任务不改变历史事件的操作时间。

## 11. 脚手架交付与开发者体验（P0 建议基线）

### 11.1 交付形态与支持边界

首版建议采用**源码模板 + 配置 + 文档化命令**，开发者复制为自己的项目后独立维护。P0 不要求发布交互式 CLI、在线生成器或运行时插件系统；名称 HonoCraft 不作为已经确认 Hono 或任何运行时、前端框架、数据库的依据。

| 交付方式 | 适用价值 | 当前取舍 |
| --- | --- | --- |
| 源码模板 | 可直接查看、修改和部署，维护链路短 | P0 建议采用 |
| 初始化 CLI / 模块生成器 | 多次创建项目时减少重复输入 | P1 按实际使用需求评估，不成为首版依赖 |
| 可热插拔平台 | 运行时安装第三方模块 | 超出本 PRD 范围 |

- 模板标注发布版本、许可证和第三方依赖许可说明；具体开源许可由维护者在发布前选择，PRD 不预设再分发授权。
- 技术设计选定一条主运行时、主数据库与主部署路径，并列明支持版本、系统前提、必要工具和网络依赖。P0 不要求同时兼容多个数据库、Serverless/Edge 及多种前端框架。
- 本地默认可通过开发邮件捕获完成所有认证流程，无需真实邮件供应商或其他付费服务。生产邮件须由部署者自行配置并验证。
- 默认不配置遥测或向模板维护者发送用户、业务及使用数据。任何后续外部分析集成单独说明采集范围与启用方式。

### 11.2 开箱启动流程

1. 获取标记版本的模板，按快速开始设置项目名、实例 URL、数据库连接和本地邮件模式；文档区分必填项、可选项与开发默认值。
2. 使用锁文件安装依赖，执行配置校验。缺失配置报出字段名与修正方式，不打印密钥，不自动使用生产资源。
3. 启动本地基础依赖并执行数据库迁移与幂等基础数据初始化；只创建权限目录和内建角色，不创建固定密码账号。
4. 启动应用和邮件任务执行器，完成部署者初始化；开发邮件只在本地捕获界面可见，不输出至常规应用日志。
5. 登录后台，邀请测试成员，完成一次分配角色与撤销会话操作；停止并重启应用，确认数据和任务仍可恢复。

文档必须给出可复制执行的准确命令和正常输出示例。提供开发启动、配置检查、代码检查、适用的类型检查、测试、生产构建、生产启动、迁移与初始化入口；具体命令名由技术设计决定，发布时不得留占位命令。清空开发数据必须显式选择目标并确认，生产启动不得自动清库或灌入演示账号。

### 11.3 业务模块接入契约

脚手架负责通用身份、授权判断和运行能力，业务模块负责资源语义及数据归属。接入文档须说明下表每项的代码位置、最小示例与验证方式；不能要求业务模块复制整套认证或直接读写凭证表。

| 接入点 | 脚手架提供 | 模块开发者负责 |
| --- | --- | --- |
| 路由与请求身份 | 标准认证入口、当前用户与会话上下文、公开端点声明方式 | 声明公开/本人/功能权限；默认拒绝未声明接口 |
| 权限与数据范围 | 权限目录注册、权限检查、授权版本变更规则 | 权限 Code、依赖与委派属性；逐资源校验拥有者及字段范围 |
| 数据与事务 | 统一迁移方式、事务入口及审计协同约定 | 业务实体、索引、并发规则；提交前权限复核和审计摘要 |
| 页面与导航 | 应用布局、权限入口、加载/空/错误状态及通用表单模式 | 业务路由、菜单、字段校验与中英文文案 |
| 错误与排障 | 稳定错误响应、request_id、脱敏日志约定 | 可公开的业务错误码；禁止返回堆栈和内部敏感字段 |
| 后台任务 | 邮件持久化投递与任务状态约定 | 如需新增其他任务，单独定义幂等、超时与恢复；不默认扩展通用队列平台 |

所有示例权限以模块命名空间区分，不污染核心目录。新增业务模块通常只增加模块代码、迁移和注册声明，不修改认证核心；若必须改核心，接入文档须解释原因与影响范围。

### 11.4 可移除的参考模块

- 提供一个“个人笔记”最小参考模块，展示列表、新建、编辑、删除；只含标题与纯文本内容，不增加协作、附件或工作流。
- 参考权限为 `example-note:read`、`example-note:create`、`example-note:update`、`example-note:delete`，写权限依赖读取；示例只允许处理本人记录，用户 B 即使持有同样权限也不能读取或修改用户 A 的笔记。
- 超级管理员拥有全部功能权限也不自动绕过该示例的资源归属检查；真正需要跨用户读取的业务必须显式设计独立权限和规则。
- 示例包含输入校验、稳定分页、错误展示和变更审计，审计只记动作与记录 ID 等必要元数据，不默认复制笔记内容。
- 示例默认仅在开发演示中启用，不纳入 `user` 基线权限或生产菜单；验证时由超级管理员为测试账号授予示例角色。
- 提供删除模块、导航、权限、演示数据与迁移的步骤。已有示例数据时须明确数据处理并执行正式迁移，不能靠删除历史迁移文件清理已部署数据库。

### 11.5 配置、定制与升级

- 品牌、语言、主题及注册策略通过第 8.4 节配置完成；数据库/邮件适配和业务模块通过明确代码边界定制。P0 不增加通用页面搭建器或任意 CSS/脚本注入设置。
- 发布包提供配置目录：名称、用途、默认值、是否敏感、是否必须及生效条件。运行时业务配置以数据库值为准；部署环境只负责基础设施、密钥和首次缺省值，不在重启时覆盖已保存业务配置。
- 对已有数据库，启动只检查兼容性，不静默执行破坏性迁移。基础权限同步保留自定义角色与业务数据；删除/重命名权限必须给出迁移和授权影响说明。
- 派生项目独立维护，模板更新不承诺自动覆盖或无冲突合并；提供版本变更记录、配置差异、数据库迁移顺序和认证/授权兼容性说明。
- 发布前备份，发布后验证登录、邀请、撤权和审计。失败时区分“可回退应用版本”与“需从备份恢复数据”；涉及不兼容结构或数据转换时不能只回退程序。

## 12. 接口契约、安全与质量要求

### 12.1 接口行为

- 成功响应结构一致；列表返回 items、分页信息和总数；错误返回稳定错误码、可展示信息、request_id 及必要字段错误。
- 401：未认证、会话过期/撤销；403：当前身份无权访问；404：资源不存在或不应向该调用方泄露其存在。
- 409：邮箱/角色 Code 冲突、乐观版本冲突、受引用角色不能删除；422：可公开说明的输入校验失败；429：限流并提供重试信息。
- 邮件类请求可返回 202 表示已受理，不将任务入队当作邮件送达。
- 找回密码等防枚举接口不使用不同状态码泄露账号是否存在。临时锁定不返回公开的账号特定原因。
- 对邀请和敏感写操作支持可识别的重复请求处理；异步邮件、页面重复点击和网络重试不能产生重复副作用。
- 使用幂等键的写请求必须绑定操作者、操作类型与请求内容；相同键和不同内容返回冲突。重试仍检查当前会话与权限，不能用历史成功结果绕过撤权；保留期限及超时后查询结果的方式写入接口文档。
- 列表排序字段使用允许清单，文本检索有长度限制；空结果返回空列表，接口不默认返回全部数据。表单不接受未声明的状态、角色、用户 ID 等字段作为赋权依据。
- 前后端共享字段、权限 Code 和错误码契约；提供可浏览的接口文档与公开/受保护端点清单。

### 12.2 安全基线

1. 密码采用适合密码存储的带盐、带工作因子的哈希算法；具体库与参数通过技术设计和目标环境验证，禁止普通散列或可逆密码加密。
2. P0 密码默认至少 15 个字符，允许长密码和粘贴，使用常见/已泄露弱密码阻断，不强制“必须大写+数字+符号”，不强制周期换密。该策略参考 [NIST SP 800-63B-4](https://pages.nist.gov/800-63-4/sp800-63b.html)，是本产品的建议基线，不构成 NIST 合规认证。
3. 生产必须 HTTPS，敏感页面不缓存认证信息。Cookie 与 CSRF、会话更新/撤销规则参考 [OWASP Session Management Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。
4. 登录与恢复返回统一公开提示，恢复凭证随机、短期、一次性，遵循 [OWASP Authentication Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html) 与 [Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)。
5. 参数化数据库访问、输出编码、严格输入校验；富文本不是首版资料字段。限制上传类型、路径与公开访问方式。
6. 密钥只来自部署配置/密钥存储，API、日志、导出和普通管理页面不得泄露；不同用途凭证不可互换。
7. 限流按目标与来源共同执行；多进程部署时不得每进程各算一份限额。代理来源信任列表明确配置。
8. 授权采用默认拒绝；管理操作覆盖目标范围、字段权限与并发场景，不能仅检查一个宽泛 `admin` 标记。
9. 不自动抓取用户提交的外链头像；邮件链接仅使用受信任的实例 URL 构造，避免任意 Host 注入。
10. 上线前验证关键依赖和配置；出现安全相关失败应返回安全错误并留可排查记录，禁止回退到免鉴权。

### 12.3 性能与容量基线

以下为待目标环境验证的首版建议目标，不是已达到的结果：

| 项目 | 验收目标 | 测试条件 |
| --- | --- | --- |
| 用户/日志列表 | P95 ≤ 500 ms | 2 vCPU / 4 GB 内存；数据库同内网；1 万用户、100 万条日志、20 并发；每次 20 条 |
| 登录 | P95 ≤ 1.5 s | 同一基准环境；5 并发完整密码校验；不包含外部 OAuth 与邮件耗时 |
| 邮件受理 | P95 ≤ 500 ms | 建立持久化任务的 API 耗时，不含供应商投递 |
| 撤权 | 成功提交后下一次受保护请求拒绝旧会话 | 包括页面已打开、旧 Cookie 重放、多进程和权限缓存 |

基准报告须记录硬件、数据库、数据规模、并发与错误率。无法满足时应分析并修订明确目标，不能只用平均响应时间代替。

### 12.4 可维护性与可恢复性

- 按认证、用户、授权、审计、邮件和配置划分职责，模块边界文档清晰；不要求微服务拆分。
- 提供环境变量示例、迁移、初始化、开发/生产部署、权限扩展、邮件配置与故障排查文档。
- 所有基础能力使用配置和明确扩展点接入业务，不通过手工改数据库来授予角色。
- 默认每日备份数据库，至少保留 7 天；首版恢复演练目标 RPO ≤ 24 小时、RTO ≤ 4 小时，最终以部署者环境确认。
- 恢复后强制使备份中的旧会话与一次性凭证失效，避免已撤销凭证被备份“复活”；管理员重新登录，邀请按需重发。
- 头像文件、数据库和解密所需密钥需要共同考虑备份；密钥另行安全保存，不能仅备份数据库却无法解密。
- 日志保留、最终个人数据清理与相关合规政策由部署者明确；本文不自动承诺特定地区合规认证。

| AC-39 | 邮箱变更被替换、取消；Pending 修正邮箱；变更后使用旧重置链接 | 仅最新请求有效；验证前不替换登录邮箱；Pending 按激活约束处理；旧邮箱凭证失效 | P0 |
| AC-40 | 相同幂等键重复提交、换请求内容、撤权后重试 | 不重复产生业务副作用；不同内容冲突；失去权限不能获取历史敏感结果或继续执行 | P0 |

**验收记录格式**：每项记录需求 ID、模板版本、环境、前置数据、操作步骤、预期与实际结果、证据位置及未解决问题。接口并发与进程崩溃等场景使用可重复的集成验证；页面操作用端到端或人工记录补足，不要求每个后台任务都有对应页面。仅修改本 PRD 不等于上述场景已通过。

## 14. 里程碑、交付物与发布门槛

| 阶段 | 交付目标 | 完成证据 |
| --- | --- | --- |
| M0：需求与技术设计 | 确认首版范围、模板交付、身份/权限规则、部署环境与主要技术选型 | PRD 评审结论、技术方案、支持矩阵、数据与接口设计 |
| M0.5：可运行模板 | 开发环境、配置校验、迁移、邮件捕获、统一命令与质量检查入口 | 干净工作副本可启动；无默认生产凭证；初始化能力随 M1 完成 |
| M1：身份闭环 | 初始化、注册/验证、登录、密码、个人中心、会话 | 可演示的成功及失效流程；关键安全验收证据 |
| M2：管理闭环 | 用户、邀请、RBAC 与超级管理员保护 | 普通管理与直接 API 越权场景验证 |
| M3：发布准备 | 审计、邮件可靠性、配置、健康、业务示例、扩展文档、升级与恢复 | P0 验收记录、开发者试用、性能报告、升级和恢复演练及部署指引 |
| M4：增强版本 | OAuth、MFA、批量邀请等经确认的 P1 能力 | 对应新增安全流程与验收通过 |

安全日志、审计和邮件应随各功能同步接入；M3 做完整性验收，而不是到最后才补安全基础。

**P0 必须交付**：

1. 可运行的应用源码、配置示例与明确的开发/生产启动方式。
2. 用户和管理员界面、接口文档与权限目录。
3. 初始化、数据库迁移、升级与备份恢复文档。
4. 标准邮件模板、发送适配和开发邮件捕获方式。
5. P0 验收记录，包含权限绕过、凭证重放、并发和依赖失败场景。
6. 已知限制、运维责任和后续扩展说明。
7. 模板版本、许可证、支持环境矩阵、锁文件、统一检查命令和持续集成配置；自动检查至少覆盖静态检查、适用的类型检查、关键集成验证与生产构建。
8. 可移除参考模块、业务接入和定制指南、配置目录、发布变更记录及升级/失败恢复说明。
9. 首次启动、模块接入与示例裁剪的试用记录；无法达到建议目标时给出原因和经评审修订的目标，不能以“文档已提供”代替试用。

**发布门槛**：所有 P0 验收场景通过；不存在已知可绕过认证、越权、泄露凭证或破坏核心一致性的问题；生产环境完成初始化与配置校验；至少一次在目标环境完成备份恢复演练。未实现的 P1/P2 不在界面或文档宣称已可用。

## 15. 评审决策与风险

以下项目区分已有建议基线与需在 M0 / 发布前确定的事项；技术栈和许可不在本轮擅自选定。评审变更后需同步更新范围、规则和验收，不应仅口头改变。

| 决策 | 建议默认 | 变更影响 |
| --- | --- | --- |
| 首版交付范围（已确认） | P0 核心闭环；OAuth、MFA、批量邀请为 P1 | 后续若调整范围，应同步阶段与对应验收 |
| 脚手架交付形态（本轮建议） | 源码模板；CLI 不进入 P0 | 若要求 CLI，需增加项目命名、目录冲突、失败回滚与生成产物验收 |
| 参考模块（本轮建议） | 可移除个人笔记，仅开发演示启用 | 更复杂的示例会扩大业务范围；移除后须保持核心验证通过 |
| 支持环境（M0 确定） | 一种主运行时、主数据库和主部署路径 | 确定后给出版本矩阵、准确命令与容量报告；当前不声称支持特定栈 |
| 分发许可（发布前确定） | 由维护者选择并核查依赖许可 | 决定模板修改、商用、再分发与声明义务，未选择前不宣称授权范围 |
| 首版登录标识 | 邮箱；用户名为 P1 | 用户名影响注册字段、唯一性与账号恢复规则 |
| 管理员保护 | 保护最后一名可用超级管理员，允许处置其余账号 | 如坚持原稿全部超级管理员不可禁用/删除，需要另定离职/泄露处置流程 |
| 初始密码 | 用户通过邀请/验证流程自行设置，无临时明文密码 | 若引入其他方式，需要额外凭证交付与强制变更规则 |
| 删除后邮箱复用 | 不复用；P1 提供恢复和后续清理方案 | 放开复用需隔离旧历史、外部身份和未消费凭证 |
| 认证与数据组件 | PRD 不锁定具体产品或库 | 技术设计需验证会话撤销、身份扩展、迁移及备份能力 |
| 目标部署环境 | 先以第 12.3 节单实例基准验证 | 最终环境影响容量、密钥、文件、限流与恢复方式 |
| 第三方登录平台 | P1 建议 Google + GitHub | 需确认供应商账号、邮箱保证及部署可用性 |
| 日志保留和数据清理 | 90/180 天日志；软删除保留历史 | 部署者的实际政策可能要求不同保留和最终删除流程 |

主要风险：邮件送达不由系统完全控制；权限委派与缓存可产生间接提权；OAuth 自动按邮箱合并可造成身份接管；删除/恢复/备份可复活旧权限或凭证；敏感日志可能成为凭证泄漏源。本文通过显式流程、事务边界、凭证撤销和脱敏减少这些风险，最终仍需技术实现验证。

## 16. 相对原稿的完善与调整

| 原稿问题 | 本版处理 |
| --- | --- |
| 核心与扩展功能混在同一层级 | 增加 P0/P1/P2、里程碑与发布门槛；扩展功能保留 |
| 邮箱/用户名、OAuth 未指定身份规则 | 明确邮箱为首版标识，增加第三方身份绑定与防自动合并规则 |
| Pending 与邀请未接受语义混用，模型漏 Session | 区分 Pending 用户与 Invite；补会话、一次性凭证和邮件任务实体 |
| 超级管理员“任何账号都不可删除/禁用” | 建议改为最后一名可用超级管理员保护，支持离职/泄露处置 |
| 管理员可以任意修正邮箱、生成临时密码 | 邮箱需独立验证；取消临时明文密码，统一用户自行设置 |
| RBAC 仅有角色/权限映射，没有委派限制 | 增加保留权限、目标管理范围、间接提权和并发保护 |
| 权限变更与旧会话的关系不明确 | 明确授权版本、撤销规则与高风险写操作的再次校验 |
| Token 有效期、重发、撤销、重复点击未定义 | 增加默认期限、用途隔离、一次性事务和 GET 不消费规则 |
| 审计保存请求完整快照，可能记录敏感值 | 改为允许字段与脱敏摘要，补失败事件和审计事务要求 |
| 原图将审计强制依附 Session | 修正为操作者/动作/目标事件，可容纳初始化、后台和匿名事件 |
| “企业级”、性能和维护性不可验收 | 增加基准条件、验收场景、恢复目标和明确交付物 |
| 密码特殊字符规则与笼统锁定策略 | 增加来源依据、长密码与弱密码阻断，区分临时锁定和业务禁用 |

### 16.1 v1.2 本轮增补

| v1.1 缺口或歧义 | 本轮处理 |
